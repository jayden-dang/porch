# Rust stack

Language is locked (E1). This is the engineering translation.

## Crate policy

Virtual workspace (`resolver = "3"`). Published package: `porch` (crates.io id free as of 2026-08-29). If that id is taken at publish time, package `porch-cli` with `[[bin]] name = "porch"`.

Slice libraries (`porch-git`, `porch-gate`, later phase crates) are `publish = false`. A crate is a use-case cluster, not a technical layer. Do not add `porch-daemon` / `porch-db` / `porch-ipc` as packages.

`default-members = ["crates/porch"]`. Inherit edition, license, rust-version, lints, and third-party versions from `[workspace]`.

Edition 2024. Pin MSRV (`1.85`) in `rust-toolchain.toml` / workspace `rust-version`. `Cargo.lock` committed.

The review CLI, `gh`, and the native agent are **external binaries**, not crates.

## Process model

```
porch (CLI, short-lived)          # crates/porch
  └─ JSON-RPC ──► porch daemon    # crates/porch-gate
                    ├─ rusqlite writer thread
                    ├─ run tasks (JoinHandle per run)
                    │    ├─ git CLI (crates/porch-git, spawn_blocking)
                    │    ├─ review CLI (later slice, process group)
                    │    └─ fixer agent (later slice, process group)
                    └─ IPC subscribers (bounded)
```

`main` should detect `daemon run` / `daemon log-sink` **before** initializing a global logger that would steal daemon stderr.

## Git

```rust
// conceptual
git::run(ctx, GitDir(&abs_bare_or_worktree), &["rev-parse", "HEAD"])
```

Always `--git-dir` or `-C` with absolute paths. `safe.bareRepository=explicit` environments (agent harnesses, CI) break cwd discovery.

Correction commits: `--no-verify` plus a temporary empty `core.hooksPath` so husky-style hooks that source missing `_/husky.sh` do not fail the disposable worktree. Do not change the user’s repo config.

## SQLite vs Tokio

One connection. WAL. `PRAGMA foreign_keys=ON`. Migrations on daemon start. Never `await` while holding the mutex across a git fetch.

## Killing children

Unix: `CommandExt::process_group(0)` (or `pre_exec` setpgid), then SIGTERM to `-pid`, then SIGKILL. Windows: create Job Object, assign child, `KILL_ON_JOB_CLOSE`. After a run: sweep processes whose cwd is that worktree (age floor so a starting run is not mistaken for a leak).

If this is deferred, mailgate-sized `cargo test` workers will leak. It is not polish.

## Services

Generated by `porch daemon install` (render is pure; install writes the file):

- macOS: `~/Library/LaunchAgents/ai.porch.daemon.<suffix>.plist` — `RunAtLoad` + `KeepAlive`
- Linux: `~/.config/systemd/user/porch-daemon-<suffix>.service` — `Type=simple`, `Restart=always`
- Windows: Task Scheduler name `porch-daemon-<suffix>` (command string rendered; no schtasks required on macOS CI)

Suffix = first **8 hex** of sha256 of canonical `PORCH_HOME`. `porch daemon start` tries the OS manager then falls back to detached `ensure_daemon`. True socket activation (`LISTEN_FDS`) is **later** (E6); always-on KeepAlive is not the only mode.

## Release (later)

`cargo-dist` or GitHub Action matrix: macos-aarch64, linux-gnu, windows. Not year-1 week 1.

## Honest cost

Same product surface will take longer in Rust (daemon + Windows jobs + service files + IPC). Benefit: dogfood on mailgate without a second toolchain, and we never wanted a nine-adapter zoo. Review quality does **not** come from rustc; it comes from the review engine.
